# Comparison methodology

The normalized model behind the home page. **The formulas are frozen** — this phase moved them,
it did not change them. `tests/baseline.test.js` asserts all 45 market × strategy × exit-year
outputs against values generated by executing the legacy prototype's own code.

---

## What is being normalized, and why

Each market dashboard reaches its own conclusion in its own currency, on its own archetype, over its
own horizon. Those conclusions are not comparable: all five markets independently score "Selective"
within four points of each other.

The dispersion an allocator needs only appears once the metrics are forced into one currency and one
model. That is the only thing this layer does.

## The invariants

| | |
|---|---|
| Currency | USD |
| Window | 15 years, uniform for every market |
| Capital structure | **Unlevered** |
| Basis | Per MW of the market's own reference archetype |
| Merchant degradation | 2%/yr, applied to merchant + services |
| Merchant revenue | Net of optimiser fees |
| Capacity revenue | At each market's contract terms, stepping down after expiry |
| Grants | Netted off capex only where the source dashboard supports it (RO 20%, PL 10%) |

```javascript
FX = { AUD: 0.66, GBP: 1.27, EUR: 1.08, JPY: 0.0064 }   // USD per unit
FX_SEED_DATE = '2026-07-28'    // illustrative mid-rates, NOT retrieved live
LIFE = 15
EXIT_Y_CONTRACTED = 0.075
EXIT_Y_MERCHANT   = 0.115
EXIT_Y_AUCTION    = 0.115      // = merchant: auction renewal is market risk
EXIT_Y_OPEX       = 0.08
```

### Why unlevered

Debt capacity differs by market for *exactly the reasons this page measures*. Assuming a capital
structure would smuggle the answer into the inputs. Instead the difference is expressed through the
exit yields: contracted cash flow is priced at 6.5%, merchant at 10.5%.

## The calculation

Per MW, in USD, for a market `m` under strategy `s` with exit year `X`:

**1. Convert and net down.**

```
merch  = merchGross × (1 − feePct/100) × fx
svc    = services × fx
grant  = capexPerMW × fx × grantPct/100
capexG = (capexPerMW + rtbPrice) × fx
opex   = opexPerMW × fx
net    = capexG − grant + non-recoverable VAT
```

### Capital cost — components, entry price and spend profile

`capexPerMW` remains the authority on what a build costs. Three optional layers sit around it, in
[`src/comparison/capex.js`](../src/comparison/capex.js), and **a market that declares none of them
produces exactly the cash-flow vector it produced before** — which is what
[`tests/baseline.test.js`](../tests/baseline.test.js) asserts without regenerating its fixture.

**`capexStack`** describes the composition of `capexPerMW`; it never replaces it. Where the two
disagree the components are scaled to the authoritative total, so a breakdown always sums to the
number on the card, and so the Investment Lab can still reprice a scenario by overriding
`capexPerMW` alone. Component shares are global until gate **G24** closes — the split is
descriptive, and only the total it reconciles to is market evidence.

**`devCostPct` and `rtbPremiumPct`** price the entry. This platform underwrites at ready-to-build,
so what is bought is a developed project, not a construction budget:

```
devCost  = capexPerMW × devCostPct/100
rtbPrice = devCost × (1 + rtbPremiumPct/100)
```

Both seed at zero. Nothing publishes an RTB premium — gate **G25** — so the model takes it as an
input and reports the implied per-MW acquisition price as an output rather than asserting one.

**`constructionMonths`** spreads the spend. Up to twelve months is a single outflow at t=0, which is
the legacy shape; beyond that the spend follows an S-curve (20/60/20 over three years, a normalised
raised cosine for longer) and first revenue moves out by the additional years. This is the channel
through which an HV transformer lead time reaches the IRR: on 2026 lead times a transformer-bound
connection is a multi-year programme, and two otherwise identical projects do not earn the same
return.

**VAT** is timing, not cost, wherever it is recoverable: charged with each construction instalment
and refunded after `vatLagMonths`, so it drags the return through working capital only. Set
`vatRecoverable: false` and it capitalises into `net` instead. Rates are statutory; the recovery lag
is gate **G27** and seeds at zero, so VAT currently costs nothing in the published model.

**2. Set the contracted line by strategy.**

| Strategy | `cap` | `cy` (years) | `post` |
|---|---|---|---|
| `cap` — capacity-backed | `contracted × fx` | `min(contractYears, 15)` | `postFactor` |
| `mer` — merchant | 0 | 0 | 0 |
| `toll` — tolled / floor | `toll × fx`, merchant and services zeroed, grant zeroed | `min(tollYears, 15)` | 0 |

**3. Build the annual series**, years 1…15:

```
capY[y] = y ≤ cy ? cap : cap × post
mchY[y] = (merch + svc) × (1 − degr/100)^(y−1)
eb[y]   = capY[y] + mchY[y] − opex
```

**4. Hold metrics.**

```
irrHold = IRR([−net, eb₁ … eb₁₅])
payback = first year where cumulative eb ≥ net
yield1  = eb₁ / net
kwPerM  = 1e6 / (net / 1000)          // kW controlled per $1M, net of grant
contractedShare = eb₁ > 0 ? capY₁ / (capY₁ + mchY₁) : 0
```

**5. Exit at year X.** The buyer acquires the remaining cash flows and assumes the remaining opex,
each priced at its own yield:

```
exitVal = PV(capY[X…], 6.5%) + PV(mchY[X…], 10.5%) − PV(opex × (15−X) years, 7%)
irrExit = IRR([−net, eb₁ … eb_X + exitVal])
moic    = (Σ eb₁…eb_X + exitVal) / net
```

`PV(arr, r)` discounts the retained tail back to year `X`, with the first retained flow one period
out.

### IRR

80-iteration bisection over `[-0.9, 2.0]`. Returns `null` when the bracket does not straddle zero —
i.e. when the cash flows have no IRR in that range. **`null` means "no IRR", never zero**; it renders
as an em dash. This matters: several merchant cases are deeply value-destroying and must show as
negative or absent, not as 0%.

## Revenue risk classes

Two models, selected by `economics.riskClass`.

### Default — contracted / merchant

Every pre-Japan market. A contracted line runs for `contractYears` then steps down by `postFactor`;
a merchant line degrades. Formulas frozen, outputs pinned by `tests/baseline.test.js`.

### `auction-renewal` — secured / renewal / merchant

For markets where capacity revenue is won one delivery period at a time and must be re-won
afterwards. Japan's Capacity Market main auction is the case this was built for.

```
secured        an executed award covering the modelled year
auctionRenewal future clearings assumed but not won — market risk
merchant       energy + incremental balancing
```

```
secY[y] = y ≤ securedContractYears ? securedContracted × fx : 0
aucY[y] = y >  securedContractYears ? auctionRenewalCurve[y − securedContractYears − 1] × fx : 0
mchY[y] = (merch + svc) × (1 − degr/100)^(y−1)
```

Exit at year X prices each stream at its own risk:

```
exitVal = PV(secY[X…], EXIT_Y_CONTRACTED 6.5%)
        + PV(aucY[X…], EXIT_Y_AUCTION    10.5%)   ← market risk, not contracted
        + PV(mchY[X…], EXIT_Y_MERCHANT   10.5%)
        − PV(opex,     EXIT_Y_OPEX        7.0%)
```

**This is the distinction that stops the model overstating Japan.** A one-year capacity award
discounted at the contracted yield would value it like a 17-year contract. `EXIT_Y_AUCTION` is set
equal to the merchant yield rather than to some intermediate number no source supports; it is a
separate constant so the treatment is explicit and can be separated later.

`securedShare` counts only executed cash flow. `contractedShare` is deliberately set equal to it —
future auction clearings are never contracted.

### Secured share vs secured tenor

Two league-table rows, because they answer different questions. A market can be three-quarters
secured for one year, or a tenth secured for fifteen. The certainty-frontier tooltip carries the
tenor alongside the share for the same reason: two points at the same x position can mean
completely different things.

## Routes to market

Four, each gated on a declared capability:

| Route | Requires | Message when unavailable |
|---|---|---|
| `cap` Capacity-backed | `capacityMarket` | No capacity mechanism |
| `mer` Merchant | `merchant` | No merchant exposure |
| `toll` Tolled / floor | `tolling` | No market precedent |
| `ltda` Long-term award | `longTermAward` | No representative award scenario loaded |

No market enables `longTermAward`. A long-term decarbonization award is won by a project, so it
describes a winner rather than the market a new entrant faces, and adding its headline payment to
full merchant revenue would double count against the award's own other-market revenue sharing. The
route is declared so the extension point is real; enabling it requires loading a representative
scenario and badging it `illus` / `project`.

Default presentation: capacity-backed where a capacity mechanism exists, merchant otherwise. For the
five migrated markets that is `cap` everywhere except Romania.

**An unavailable route is never modelled as zero.** The engine returns `{ na: [en, zh] }`. Romania
therefore has one row in the `$1M` engine, not a 0% capacity row; GB is the only market with three.

## Metric catalogue

`src/comparison/metrics.js` holds the thirteen league-table rows as data: id, bilingual label,
direction, ranking accessor, formatter, and whether the metric is rank-comparable at all.

Three rows are **context-only** and are never ranked or coloured:

- **Composite score** — each market scores itself on its own basis. Comparing them is meaningless,
  which is why the row is greyed and italic and says so in its own label.
- **Pipeline / operating ratio** — each market computes it differently.

For the rest, best and worst are found by sorting a copy of the values and taking the extremes. On a
tie the first market in registry order wins the highlight. Markets whose result is unavailable are
excluded from ranking rather than counted as worst.

Packaging the rows as a catalogue is what makes the future "compare only these metrics across only
these markets" UI a filter rather than a rewrite. That UI is deliberately not built.

## Where the prose comes from

Originally the `why(...)` footnotes and the "Key readings" section were authored prose naming
specific markets and quoting specific numbers. Adding three Japanese allocation points made several
of those statements false — a hand-written "four times out of five" does not survive an eighth
market — so they were rewritten.

**"Key readings" is now computed.** Each finding states a structural claim that holds at any N, and
fills the markets and numbers in from the engine on every render. A finding that stops being true
changes its own text rather than going quietly stale.

**The `why(...)` footnotes are now structural.** They describe how to read a chart rather than what
the chart currently says, so they name no winners and quote no values.

If a data refresh overturns the *shape* of a finding — merchant IRRs no longer sorting by duration,
say — that is a market-regime change worth a committee discussion, not a model recalibration.

## Verification

```bash
npm test                 # 74 assertions, including 45 baseline cases
npm run test:baseline    # regenerate the fixture from the legacy prototype
```

`tests/fixtures/generate.mjs` carries lines 683–811 of the original prototype — its normalization
layer — transcribed verbatim, and runs them in Node to dump every output. It is a copy, not a
reader: the prototype itself has been removed from the repository and its history
([`legacy/README.md`](../legacy/README.md)), and the generator is unaffected because it never opened
that file. `tests/baseline.test.js` compares the modular engine
against it at a relative tolerance of 1e-12, and separately pins the headline figures the prototype
quotes in its own commentary.

## Known limitations

These are properties of the model as inherited, recorded rather than fixed:

- **FX rates are illustrative mid-rates.** Replace with live rates before any transaction use.
- **All inputs are seed-derived.** Every figure carries the quality badges of its source dashboard.
- **The 15-year window truncates Poland's contract**, which runs 17 years. Poland's `capNote` says so.
- **Exit assumes a buyer exists** at year X. Where the exit share of total return is high, that
  assumption is doing a lot of work — which loops back to contracted share, since that is what
  defines the buyer universe.
- **The hold-IRR chart passes 0 for unavailable routes** so that no bar is drawn. The engine returns
  `na` correctly; the chart's substitution is preserved from the prototype to avoid a visual change.
  See `migration-notes.md`, bug B3.
